# DAA Assignment 4 — Dynamic Programming and String Algorithms

## GitHub Repository

[View the project on GitHub](https://github.com/Aknur4213/DAA-4)
## Project Description

This project implements and compares five algorithms from Dynamic Programming and String Algorithms.

The project follows the City Search & Spell-Check scenario, where Edit Distance measures differences between words and String Search finds patterns inside text.

## Implemented Algorithms

### Edit Distance

1. **Recursive Edit Distance** — Direct recursion without memoization.
2. **DP Table** — Bottom-up dynamic programming using a two-dimensional table.
3. **Two Rows** — Memory-optimized dynamic programming using two arrays.

### String Search

4. **Naive Search** — Checks every possible starting position in the text.
5. **KMP Search** — Uses the Longest Prefix Suffix (LPS) array to avoid unnecessary repeated comparisons.

## Build Instructions

Open the project in IntelliJ IDEA with JDK 25 and Maven configured.

To compile and package the project, run:

```bash
mvn clean package
```

## Running Tests

Run all JUnit 5 tests using:

```bash
mvn test
```

The tests verify:

- Edit Distance reference values.
- Empty-string cases.
- Agreement between three Edit Distance implementations on 100 random inputs.
- Correct LPS arrays.
- String Search reference values.
- Overlapping matches.
- Invalid and longer-than-text patterns.
- Agreement between Naive and KMP on 100 random inputs.

## Running the Benchmark

After compiling the project, run:

```bash
java -cp target/classes daa.bench.Benchmark
```

Alternatively, run the `Benchmark` class directly in IntelliJ IDEA.

The benchmark executes each experiment five times and records execution time and algorithm operations.

Results are saved to:

`results/results.csv`

The CSV contains 200 data rows, representing five runs for each algorithm, input type, and input size.

## Experiment Design

Edit Distance is tested using EQUAL and DIFFERENT strings.

String Search is tested using RANDOM and WORST_CASE inputs.

A fixed random seed of 42 ensures reproducible input generation.

Execution time is measured using `System.nanoTime()`, with the median of five runs reported.

Operation counters are updated inside the algorithms.

The complete experiment design, graphs, and analysis are available in [REPORT.md](REPORT.md).
